# 3. 원자적 경계 (고정 분모: 21)

## Context/runtime 경계 (12)

| ID | 넘지 말아야 할 선 |
| --- | --- |
| **TB-1** | 브라우저는 공개 영역입니다. 비밀값이나 최종 권한 판정을 브라우저에 배포하지 않으며, 최종 권한은 서버가 소유합니다. |
| **TB-2** | 외부 값은 경계에서 검증하고 내부 형식으로 변환합니다. |
| **SD-1** | 생성 파일은 산출물로 취급합니다. 원본·생성기를 수정한 뒤 다시 생성합니다. |
| **SD-2** | runtime import cycle을 만들지 않습니다. |
| **ST-1** | 각 사실에는 최종 소유자가 하나만 있어야 합니다. 복제본은 동기화 또는 무효화 소유자를 밝혀야 합니다. |
| **ST-2** | optimistic 변경이나 여러 단계 변경이 실패하면 실제 결과에 맞게 UI를 조정합니다. |
| **ST-3** | 서로 경쟁하는 비동기 결과에는 어떤 결과를 적용할지 명시적인 규칙이 있어야 합니다. |
| **RT-1** | 실패를 성공처럼 조용히 표시하지 않습니다. |
| **RT-2** | 시작한 요청, listener, timer, subscription, observer는 결국 정리합니다. |
| **IC-1** | route, props, API, event, storage 계약을 바꾸면 consumer, migration·transition 동작, 검증을 함께 갱신합니다. |
| **UX-1** | loading, empty, error, success, stale 상태가 실제 결과와 모순되지 않아야 합니다. |
| **UX-2** | 상호작용 컨트롤은 프로젝트에 맞는 의미, 이름, keyboard·focus 동작, 실패 후 복구 방법을 제공해야 합니다. 이곳에서는 특정 WCAG 수치를 강제하지 않습니다. |

## 코드 설계·성능·보안 경계 (5)

| ID | 넘지 말아야 할 선 |
| --- | --- |
| **CQ-1** | 프로젝트에 적용되는 코드 품질 gate는 통과 조건과 적용 범위가 명시되어야 하며, 제외·우회에는 소유자와 만료 조건이 있어야 합니다. |
| **CQ-2** | 비즈니스 규칙에는 최종 구현 소유자가 하나만 있어야 하며 UI 컴포넌트가 같은 규칙의 경쟁 소유자가 되어서는 안 됩니다. 공유하거나 독립적으로 검증해야 하는 규칙은 명시된 모듈 경계와 공개 계약을 통해 소비합니다. |
| **PQ-1** | 사용자에게 제공되는 주요 route와 흐름에는 적용되는 성능 지표, 기대값 출처, 측정 환경, 목표, 소유자와 검증 또는 모니터링 지점이 정의되어야 합니다. 성능 budget의 제외·초과에는 소유자와 만료 조건이 있어야 합니다. |
| **SQ-1** | 적용되는 보안 통제와 발견된 취약점에는 검증·처리 기준, 소유자 및 예외 만료 조건이 있어야 합니다. |
| **SQ-2** | 신뢰하지 않는 값을 화면에 출력할 때는 출력 컨텍스트에 맞게 안전하게 처리합니다. Raw HTML·DOM 삽입은 사용하지 않거나 승인된 sanitization 경계를 거쳐야 하며, 우회에는 소유자와 검증 근거가 있어야 합니다. |

## 검토·근거 경계 (4)

| ID | 넘지 말아야 할 선 |
| --- | --- |
| **VP-1** | gate를 통과하기 위해 테스트, 타입, lint를 약화하지 않습니다. |
| **VP-2** | 완료라고 말할 때는 실제 실행한 명령어, 결과, 환경 근거를 함께 제시합니다. |
| **VP-3** | 요청된 범위 밖의 변경을 섞지 않습니다. |
| **RP-1** | 실행 근거는 선언된 패키지 관리자, lockfile, CI, 환경에서 재현 가능해야 합니다. |

VP/RP 4개 ID는 근거·검토에 관한 것입니다. CQ/PQ/SQ 5개 ID는 코드 설계·성능·보안 최소선에 관한 것이고, TB/SD/ST/RT/IC/UX 12개 ID는 Context/runtime에 관한 것입니다. 보고서는 하나의 21개 ID 분모를 유지하면서 세 그룹을 분리해 보여줘야 합니다.

`TB-2`의 입력 경계 검증과 `SQ-2`의 출력 컨텍스트 보호는 서로 대신하지 않습니다. 구조적으로 유효한 값도 HTML, DOM, URL 또는 script 관련 출력 위치에서는 위험할 수 있으므로 두 경계를 독립적으로 판단합니다.
